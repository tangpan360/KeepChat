# V1 Module Design

## 目的
本文件用于定义 KeepChat 在当前阶段的模块划分与职责边界，帮助后续进入具体设计和开发时保持结构清晰。

本文件关注：
- 当前版本需要哪些模块
- 每个模块负责什么
- 模块之间如何分工
- 哪些能力暂时不纳入当前阶段

本文件不展开数据库表、API 字段和具体框架代码结构。

## 当前阶段设计目标
- 保持模块边界清晰
- 采用模块化单体，不提前拆微服务
- 前端、后端、AI 编排和存储职责分开
- 当前只覆盖 V1 所需能力，不提前铺开未来所有能力

说明：
- 本文件同时包含 `V1 核心模块` 与 `V1 后续优先模块`。
- 对于已确定但暂不作为第一批实现重点的能力，本文件会保留模块概念，但不要求立即进入开发。

## 顶层模块划分
当前建议将系统按以下几类模块理解：

1. 插件端主交互模块
2. 插件端网页增强模块
3. 插件端配置模块
4. 后端主应用模块
5. AI 编排模块
6. 存储与基础设施模块

---

## 一、插件端主交互模块

### 1. 侧边栏聊天模块
这是当前插件端最核心的模块。

职责：
- 展示当前会话内容
- 提供输入框
- 展示流式回复
- 展示当前默认模型
- 支持新建会话与切换会话
- 展示图片待发送状态
- 展示引用托盘

负责的功能：
- 文本聊天
- 图片问答
- 多轮追问
- 复制消息
- 编辑消息
- 删除消息
- 重新生成某条回复

不负责：
- 网页选区监听
- 动作配置管理
- 模型底层调用

### 2. 历史会话列表模块
该模块服务于会话管理和切换。

职责：
- 展示会话列表
- 按最近更新时间倒序排序
- 展示标题、当前默认模型、更新时间、消息数
- 提供重命名和删除入口

负责的功能：
- 新建对话
- 切换对话
- 会话总览信息展示

不负责：
- 单条消息内容渲染
- 网页增强动作

### 3. 引用托盘模块
这是输入框上方的上下文容器。

职责：
- 展示已加入但未发送的引用片段
- 支持多段不连续引用
- 支持删除单段引用
- 区分“引用内容”和“用户问题”

负责的功能：
- 引用片段展示
- 引用片段管理
- 和输入框一起提交上下文

不负责：
- 自定义动作自动发送
- 当前网页整体问答逻辑

### 4. 模型切换与能力提示模块
该模块负责前端层的模型状态展示和能力提示。

职责：
- 展示当前默认模型
- 提供模型切换入口
- 检查当前待发送内容与模型能力是否匹配
- 在模型不支持图片时提示切换
- 体现默认最近 `10` 轮历史窗口的前端规则

负责的功能：
- 当前模型切换
- 图片能力校验提示
- 每条历史消息的真实模型名称展示

不负责：
- 模型实际调用
- 模型路由策略

---

## 二、插件端网页增强模块

### 5. 网页选区悬浮按钮模块
该模块运行在普通网页场景中。

职责：
- 感知用户选中文本
- 展示悬浮按钮
- 触发默认动作和自定义动作
- 受总开关控制

负责的功能：
- `引用`
- `解释`
- 自定义动作入口

当前规则：
- 自定义动作统一自动发送
- 不做站点级控制

不负责：
- 当前网页整体问答
- 动作配置管理
- 历史会话管理

### 6. 当前网页问答入口模块
该模块是侧边栏中的网页整体问答入口。

职责：
- 在侧边栏提供独立图标按钮
- hover 显示 `基于当前网页提问`
- 为后续网页整体问答预留清晰入口

当前阶段只负责：
- 入口存在
- 入口语义清楚

当前不负责：
- 网页正文抽取细节
- 网页问答具体流程
- 网页定位与高亮

### 7. 页面联动模块（后续增强预留）
当前不作为 V1 核心实现，但应在模块层面预留概念。

后续职责可能包括：
- 网页答案定位
- 原文匹配
- 高亮
- 索引跳转

当前阶段：
- 只作为未来模块预留
- 不进入当前开发重点

---

## 三、插件端配置模块

### 8. Options 配置页模块
该模块是插件设置与管理入口。

职责：
- 管理自定义动作
- 管理动作名称与提示词
- 管理动作启用状态与排序
- 后续可承载模型配置和 API 配置

负责的功能：
- 动作管理页
- 后续 BYOK 设置入口
- 基础偏好设置

不负责：
- 侧边栏会话主交互
- 网页悬浮按钮显示逻辑

### 9. 本地状态管理模块
这是插件内部的轻量状态存储层。

职责：
- 保存输入草稿
- 保存当前未发送的引用托盘状态
- 保存 UI 开关状态
- 保存最近会话状态

适合存储：
- 临时状态
- 短期体验数据

不适合存储：
- 正式会话历史
- 长期用户资料
- 附件主数据

---

## 四、后端主应用模块

### 10. 会话与消息模块
这是后端的主业务模块之一。

职责：
- 管理会话
- 管理消息
- 读取与保存历史
- 提供会话列表所需数据

负责的功能：
- 会话创建
- 会话切换所需数据读取
- 消息读取与写入
- 会话级元信息返回

不负责：
- 模型具体调用
- 网页选区监听

### 11. 附件与上下文模块
该模块负责图片、引用内容和后续上下文对象的管理。

职责：
- 接收图片附件
- 管理引用内容
- 管理当前待发送上下文对象
- 为后续网页、PDF 上下文扩展预留统一入口

当前负责：
- 图片附件
- 引用片段

后续扩展：
- 当前网页上下文
- PDF 片段
- 多网页资料片段

### 12. 用户与配置模块
该模块服务于登录、配置和后续同步能力。

职责：
- 用户身份信息
- 用户设置
- 自定义动作的云端保存
- 后续登录与同步能力

当前阶段判断：
- 登录不强制
- BYOK 需要在结构上预留

---

## 五、AI 编排模块

### 13. 对话编排模块
当前建议用 LangChain 作为主要 AI 实现框架，但在模块职责上只把它视为 AI 能力层。

职责：
- 读取当前会话上下文
- 组织用户输入、引用片段、图片等内容
- 调用当前选中模型
- 返回流式结果

负责的功能：
- 文本对话
- 图片问答
- 当前会话继续追问

当前不要求：
- 复杂 agent 工作流
- 多文档 RAG
- PDF 编排

### 14. 模型能力校验模块
该模块负责模型能力层面的判断，而不是 UI 表现。

职责：
- 判断当前模型是否支持图片
- 判断“当前提交 + 最近 10 轮历史上下文”是否可被目标模型处理
- 将能力边界结果返回给前端

作用：
- 保证“模型切换”与“当前提交内容”之间的规则一致
- 当前阶段如果目标模型不支持相关输入类型，应直接提示，不做自动兼容或自动裁剪

### 15. 网页问答模块（后续增强）
当前暂不展开实现，但在模块设计上应独立出来。

后续职责：
- 当前网页正文抽取后问答
- 短篇网页整页注入
- 证据原文返回
- 后续定位能力支持

当前阶段：
- 保留模块概念
- 不进入 V1 核心实现

---

## 六、存储与基础设施模块

### 16. 云端主存储模块
当前正式数据建议以云端为主存储。

负责：
- 会话历史
- 用户设置
- 自定义动作
- 附件元数据
- 后续网页 / PDF / 资料数据

作用：
- 为多端同步预留
- 为未来平台化预留

### 17. 本地缓存模块
本地缓存用于承接轻量交互状态。

负责：
- 草稿
- 引用托盘临时状态
- UI 状态
- 最近会话状态

作用：
- 提升交互流畅性
- 降低纯云端依赖带来的使用门槛

### 18. 基础设施服务模块
这是底层支撑层，不直接面向用户。

职责：
- 鉴权能力
- 数据库存储
- 文件存储
- 后续日志与监控

当前方向：
- 尽量复用成熟平台

---

## 当前不进入 V1 核心实现的模块
以下模块当前不进入 V1 核心设计与开发重点：
- 多网页问答模块
- PDF 导入与阅读模块
- PDF 问答模块
- 网页答案定位与高亮模块
- 多文档 RAG 模块
- 论文阅读器模块
- 论文编辑器模块
- diff 审核模块
- 复杂 agent 工作流模块

## 当前模块设计原则
- 前端主交互与网页增强分开
- `options` 配置页与聊天主界面分开
- 会话管理、上下文管理、模型编排分开
- 当前网页问答入口与选中文本增强体系分开
- 本地缓存与云端主存储分开
- 当前模块设计按长期分层考虑，但按当前版本轻量实现

## 当前使用建议
- 如果后续开始讨论实现顺序，应先按本文件的模块边界分任务。
- 如果后续开始细化接口和数据结构，应保持模块职责不混淆。
- 如果某个后续增强能力被正式纳入当前版本，应同步更新 `feature-structure.md` 与 `v1-user-flows.md`。
