# Feature Structure

## 目的
本文件用于整理 KeepChat 当前阶段已经讨论清楚的产品功能结构，作为后续继续细化 V1 交互、模块设计与实现顺序的参考基线。

本文件关注的是“产品有哪些功能模块、每块负责什么、当前做到什么程度”，不展开底层实现细节。

说明：
- 本文件包含 `V1 核心能力` 与 `V1 后续优先能力` 两层内容。
- 这里的“当前版本功能结构”表示当前已确认的产品结构，不等于这些能力都必须在第一批实现中一次做完。

## 当前产品定位
KeepChat 当前是一款基于 Chrome 原生 `sidePanel` 的 AI 侧边栏助手，面向普通用户，优先提供：
- 通用聊天
- 图片问答
- 网页选中文本增强
- 快捷动作执行
- 后续扩展到当前网页问答

长期来看，产品将逐步演进到：
- 当前网页整体问答
- 网页答案定位与高亮
- 多网页问答
- PDF 问答
- 知识库 / RAG
- 论文阅读与写作平台

## 当前版本功能结构

### 1. 侧边栏核心聊天区
这是当前产品的主入口。

包含：
- 打开 Chrome 原生侧边栏
- 文本聊天
- 多轮对话
- 流式回复
- 输入框提问
- 继续追问

当前约定：
- 使用 Chrome 原生 `sidePanel`
- 快捷键暂时不做
- 侧边栏是当前阶段的主要交互入口

### 2. 历史会话管理
产品需要支持多会话使用，而不是所有内容都混在一个聊天窗口中。

包含：
- 新建对话
- 会话列表
- 切换对话
- 重命名
- 删除

列表项当前建议展示：
- 对话标题
- 当前默认模型名
- 最近更新时间
- 消息总数
- 重命名操作
- 删除操作

排序规则：
- 按最近更新时间倒序

标题规则：
- 默认取第一条用户消息前若干字作为标题
- 当前阶段不依赖 AI 自动生成标题

### 3. 对话编辑能力
对话不只是静态记录，还需要支持整理与调整。

包含：
- 复制任意一条消息
- 编辑任意一条用户输入
- 编辑任意一条模型输出
- 重新生成某条模型回复
- 删除任意轮次内容

当前产品理解：
- 会话内容可调整、可整理、可继续基于当前保存状态对话
- 当前文件只定义产品能力，不限定底层如何实现

### 4. 模型选择与切换
同一个会话中允许切换模型，不要求整段对话只绑定单一模型。

包含：
- 当前默认模型选择
- 会话内切换模型
- 每条模型回复显示真实模型名

显示规则：
- 用户名称显示 `You`
- 模型消息显示该条回复真实使用的模型名
- 会话列表中显示当前默认模型名

模型切换规则：
- 会话内允许切换模型
- 当前发送是否允许，取决于“当前这次提交内容”是否超出目标模型能力
- 默认只携带最近 `10` 轮历史上下文，以控制 token 成本
- 如果当前模型不支持本次请求涉及的输入类型，则直接提示切换模型，不做自动兼容或自动裁剪

### 5. 图片问答
当前版本支持基础多模态对话。

包含：
- 上传图片
- 拖拽图片到侧边栏
- 图片与文本联合提问
- AI 对图片内容进行解释、总结或问答

规则：
- 若当前模型不支持图片，应提示切换模型
- 默认只携带最近 `10` 轮历史上下文参与请求
- 若这部分上下文中仍包含当前模型无法处理的输入，则直接提示切换模型

### 6. 网页选中文本增强
这是当前最有产品特色的能力之一。

触发方式：
- 用户在普通网页中选中文字后，出现悬浮按钮

默认按钮：
- `引用`
- `解释`

自定义按钮：
- 用户可以自己定义按钮名称与提示词
- 例如：`日语`、`英文`、`总结`、`改写`

当前规则：
- 自定义按钮统一走“直接自动发送”
- 不进入引用托盘

### 7. 两类动作模式
当前产品中，网页增强操作分为两类。

#### 引用模式
点击 `引用` 后：
- 不自动发送
- 将选中内容加入输入框上方的引用托盘
- 支持多段、不连续引用
- 支持删除某一段
- 用户补充问题后统一发送

适合：
- 收集上下文
- 多段组合提问
- 复杂问答

#### 快捷动作模式
点击 `解释` 或任意自定义按钮后：
- 自动将“预设提示词 + 当前选中内容”组合
- 直接自动发送
- 不进入引用托盘

适合：
- 翻译
- 解释
- 总结
- 改写

### 8. 引用托盘
引用托盘是输入框上方的上下文容器。

包含：
- 展示已加入但未发送的引用内容
- 支持多段不连续引用
- 支持删除某一段引用
- 用户补充问题后统一发送

设计意义：
- 区分“引用内容”和“用户问题”
- 为后续当前网页片段、网页图片片段、PDF 片段等能力预留统一容器

### 9. 快捷动作系统
自定义动作不是临时按钮，而是一个独立功能模块。

当前应支持：
- 默认动作：`引用`、`解释`
- 自定义动作
- 自定义动作直接自动发送

后续可增强：
- 动作排序
- 启用 / 禁用
- 分类
- 导入 / 导出模板

### 10. 当前网页问答入口
当前网页整体问答不放在选中文本悬浮按钮里，而是单独作为侧边栏入口。

当前方向：
- 侧边栏中提供一个独立图标按钮
- 鼠标悬停提示：`基于当前网页提问`

当前阶段暂不细化：
- 按钮点击后的完整行为
- 页面正文抽取方式
- 页面上下文展示方式

这些留到后续专门设计时再展开。

### 11. 动作管理页
动作配置不放在聊天区内部，而是单独提供配置入口。

当前决定：
- 动作管理页放在独立的 `options` 页面

当前至少应支持：
- 动作名称
- 提示词
- 启用 / 禁用
- 排序

### 12. 悬浮按钮控制
需要允许用户控制网页选中文本悬浮按钮是否启用。

当前决定：
- 提供简单总开关
- 不做站点级控制

### 13. 存储与身份
当前推荐方案为：
- 本地缓存临时状态
- 云端主存储正式数据

本地适合存：
- 当前输入草稿
- 当前引用托盘
- UI 开关状态
- 最近会话状态

云端适合存：
- 会话历史
- 用户设置
- 自定义动作
- 附件记录
- 后续网页 / PDF / 资料数据

身份策略：
- 当前不强制登录
- 前期考虑支持用户自定义 API / BYOK

## 后续增强方向

### 1. 当前网页整体问答
当前方向：
- 短篇网页优先整页注入
- 不优先对短文做分块 RAG

适合回答：
- 这篇博客讲了什么
- 博客中提到了哪些模型方法
- 作者的核心观点是什么

### 2. 网页答案定位与高亮
后续目标：
- 模型给出答案
- 返回相关原文证据
- 页面中做文本匹配
- 匹配成功后高亮
- 侧边栏中提供小索引并支持跳转

当前判断：
- 很有价值
- 但不纳入当前 V1 核心实现

### 3. 多网页问答
后续目标：
- 支持多个网页作为资料集合
- 在同一对话中汇总或对比多个网页

### 4. PDF 相关能力
后续可能支持：
- PDF 导入
- PDF 问答
- PDF 阅读
- PDF 片段定位
- 多 PDF RAG

当前不主打：
- 浏览器原生 PDF 选中悬浮按钮

### 5. 长期平台化能力
长期方向包括：
- 论文阅读器
- Markdown 渲染
- 标注与翻译
- AI 写作
- AI 改写
- diff 对比
- 接受 / 拒绝修改

## 当前不纳入 V1 核心的内容
- 浏览器快捷键默认方案
- PDF 选中悬浮按钮
- 多网页资料集合问答
- PDF 上传与解析
- 多文档 RAG
- 复杂 agent 工作流
- 论文阅读器
- 论文编辑器
- diff 审核
- 微服务化架构
- 站点级悬浮按钮控制

## 当前已确定的设计原则
- 使用 Chrome 原生 `sidePanel`
- 当前网页问答入口独立于选中文本增强体系
- 自定义动作统一自动发送
- 引用动作用于收集上下文
- 会话列表按最近更新时间倒序
- 每条模型消息显示真实模型名
- 前期文档保持轻量，不继续扩散总纲类文档

## 当前仍可后续细化的点
以下内容已经有方向，但暂时不需要在本文件里做更细定义：
- 当前网页问答按钮点击后的完整行为
- BYOK 的具体 provider 支持策略
- 动作管理页的完整字段与交互
- 会话编辑与删除在界面中的具体表现
