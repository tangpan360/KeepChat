# V1 User Flows

## 目的
本文件用于整理 KeepChat 在当前阶段的用户交互流程，帮助后续继续细化界面设计、模块拆分与实现顺序。

本文件分为两层：
- `V1 核心流程`：当前版本优先保证顺畅可用的主链路
- `V1 后续优先流程`：已经讨论清楚、但可作为后续增强的网页交互流程

## 设计原则
- 先保证主链路顺畅，再逐步扩展网页增强能力。
- 交互尽量轻量，避免打断正常网页阅读。
- 所有上下文都应通过用户显式操作进入会话。
- 当前产品强调“可用、直接、低打扰”，不追求第一版功能过满。

## V1 核心流程

### 1. 打开侧边栏并开始聊天
目标：用户安装插件后，可以直接打开侧边栏并开始一段新的对话。

流程：
1. 用户打开插件侧边栏。
2. 看到当前会话或空白新会话界面。
3. 在输入框中输入问题。
4. 点击发送。
5. 模型开始流式回复。
6. 用户继续追问或开始新的会话。

要求：
- 侧边栏应始终作为当前主要交互入口。
- 不要求用户先配置复杂设置才能开始基础聊天。

### 2. 文本问答流程
目标：让普通文字问答成为最稳定的主链路。

流程：
1. 用户输入文本问题。
2. 系统读取当前会话上下文。
3. 发送到当前默认模型。
4. 侧边栏流式展示回复。
5. 用户可以继续追问、复制、编辑或重新生成。

要求：
- 普通文本问答应是最顺畅、最稳定的交互。
- 会话内允许持续多轮追问。

### 3. 图片问答流程
目标：支持用户通过上传或拖拽图片发起图文问答。

流程：
1. 用户上传图片或拖拽图片到侧边栏。
2. 图片显示在当前待发送区域。
3. 用户补充问题或直接发送。
4. 如果当前模型支持图片，则正常发送并流式返回。
5. 如果当前模型不支持图片，则提示切换模型。

要求：
- 默认只携带最近 `10` 轮历史上下文。
- 当前发送是否允许，按“当前这次提交内容 + 最近 10 轮历史上下文”与模型能力共同判断。
- 如果当前模型不支持本次请求涉及的输入类型，则直接提示切换模型，不做自动兼容处理。

### 4. 新建会话与切换会话流程
目标：支持用户管理多个主题不同的对话。

流程：
1. 用户点击 `新建对话`。
2. 系统创建空白会话并清空当前输入上下文。
3. 用户开始新的聊天。
4. 历史会话列表按最近更新时间倒序展示。
5. 用户可以点击任意会话切换查看和继续对话。

要求：
- 每个对话标题默认取第一条用户消息前若干字。
- 会话列表应展示标题、当前默认模型、最近更新时间、消息总数。

### 5. 模型切换流程
目标：支持同一会话中切换模型，但不让能力边界变得混乱。

流程：
1. 用户查看当前默认模型。
2. 用户切换到另一个模型。
3. 下一次发送默认使用新模型。
4. 历史消息仍保留原来实际使用的模型名称。

要求：
- 当前默认模型只决定“下一次发送”。
- 每条历史模型消息显示真实生成模型。
- 历史消息的模型名称不会因当前切换而改变。
- 默认请求窗口为最近 `10` 轮历史。
- 若最近 `10` 轮内存在当前模型无法处理的输入内容，则应直接提示用户切换模型。

### 6. 会话编辑与整理流程
目标：支持用户整理当前会话内容，而不仅仅是被动查看历史。

流程：
1. 用户对任意一条消息执行复制、编辑、删除或重新生成。
2. 修改保存后，当前会话内容发生更新。
3. 后续继续对话时，模型读取当前保存后的上下文。

说明：
- 当前阶段先定义产品能力，不在本文件限定底层实现方式。
- 重点是把“会话可整理、可继续使用”的体验定清楚。

### 7. 动作配置入口流程
目标：让用户能管理自己的快捷动作。

流程：
1. 用户进入插件的 `options` 页面。
2. 查看默认动作与自定义动作。
3. 配置动作名称、提示词、启用状态和排序。
4. 保存后，动作在网页选中文本场景中生效。

要求：
- 动作配置页放在独立的 `options` 页面。
- 当前不把动作配置塞进聊天主界面。

## V1 后续优先流程

### 8. 选中文本 -> 引用流程
目标：让用户把网页中的多段内容加入到对话上下文中，再统一提问。

流程：
1. 用户在普通网页中选中一段文本。
2. 页面出现悬浮按钮。
3. 用户点击 `引用`。
4. 该段文本加入输入框上方的引用托盘。
5. 用户继续选中其他段落并重复加入。
6. 用户删除不想保留的某一段引用。
7. 用户在输入框中补充问题。
8. 用户点击发送，引用内容与问题一起提交。

要求：
- 支持多段不连续引用。
- 引用内容与用户问题要分开展示。

### 9. 选中文本 -> 解释流程
目标：让用户对某一段网页文本快速执行默认动作。

流程：
1. 用户选中网页中的一段文本。
2. 页面出现悬浮按钮。
3. 用户点击 `解释`。
4. 系统将默认提示词与当前选中内容组合。
5. 内容自动发送到侧边栏会话。
6. 模型返回解释结果。

要求：
- `解释` 属于快捷动作模式。
- 不进入引用托盘。

### 10. 选中文本 -> 自定义动作流程
目标：让用户通过预设动作快速处理网页选中文本。

流程：
1. 用户在 `options` 页面中预先配置自定义动作。
2. 用户在网页中选中文字。
3. 页面出现悬浮按钮。
4. 用户点击某个自定义动作，例如 `日语`。
5. 系统将该动作的提示词与当前选中内容组合。
6. 自动发送到当前会话。
7. 模型返回结果。

要求：
- 自定义动作统一自动发送。
- 当前不支持自定义动作进入引用托盘。

### 11. 悬浮按钮开关流程
目标：避免网页阅读被长期打扰。

流程：
1. 用户进入设置或相关控制入口。
2. 关闭悬浮按钮总开关。
3. 网页选中文字时不再显示悬浮按钮。
4. 用户重新开启后恢复。

当前约定：
- 只做总开关
- 不做站点级开关

### 12. 当前网页问答入口流程
目标：为后续整页网页问答预留一个清晰入口。

流程：
1. 用户在侧边栏看到独立图标按钮。
2. 鼠标悬停显示：`基于当前网页提问`
3. 用户点击该入口。
4. 后续再根据产品设计决定具体行为，例如读取正文、提示提问、进入网页问答模式等。

当前阶段说明：
- 只确定入口形态
- 不在本文件中展开该能力的内部细节

## 当前不纳入本文件细化的内容
- 当前网页问答的完整行为细节
- 网页答案定位与高亮
- 多网页问答
- PDF 交互流程
- 多文档 RAG 流程
- 平台级论文阅读与写作流程

## 当前使用建议
- 如果后续要继续细化 UI 和实现顺序，应先以本文件为交互基线。
- 如果后续要做模块划分，应优先围绕本文件中的主流程拆分模块。
- 如果后续某个流程被正式提升为当前版本重点，应同步回写 `v1-scope.md` 和 `feature-structure.md`。
