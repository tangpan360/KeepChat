# Project Conventions

## 目的
本文件用于沉淀当前项目的基础约定，降低后续讨论和实现过程中的反复沟通成本。

本文件强调的是当前阶段适用的工作共识，不追求面面俱到，也不提前约束过多未来细节。

## 当前阶段判断
- 当前重点是明确 V1，并围绕 Chrome 侧边栏 AI 助手推进。
- 当前优先验证通用聊天、图片问答、快捷动作和网页辅助能力。
- 当前不提前实现 PDF 知识库、论文平台、复杂 RAG 和重型 agent 系统。

## 工作方式约定
- 先讨论清楚，再开始实现。
- 涉及新增重要目录、引入重依赖、切换技术路线时，优先先确认方案。
- 优先小步推进，不一次性铺开大量未来结构。
- 如果当前只是在讨论分析阶段，不提前进行实现。

## 文档约定
- 项目文档统一放在 `docs/` 目录。
- 文档优先简洁清晰，避免写成过度复杂的大而全手册。
- 文档内容优先记录长期有效的结论、原则和边界。
- Markdown 文件统一使用 UTF-8 编码。

## 架构约定
- 当前架构按长期分层思考，但按当前阶段轻量实现。
- 前期采用模块化单体，不提前微服务化。
- 客户端、业务层、AI 能力层、基础设施层应保持边界清晰。
- LangChain 当前作为 AI 实现层使用，不直接作为整个产品的数据骨架。
- 鉴权、数据库、存储等基础设施尽量优先复用成熟平台。

## 产品约定
- Chrome 插件是当前阶段的主要入口。
- 当前版本优先做“可直接使用”的产品体验，而不是过早做重平台能力。
- 网页增强能力应通过显式用户操作进入会话，不做默认隐式抓取。
- 插件是入口，长期的论文阅读与写作平台是后续重场景产品。

## 提交约定
- Git commit 规范遵循 `docs/git-commit-guidelines.md`。
- 一个 commit 尽量只表达一件事。
- 提交信息应清晰反映改动意图。

## 后续推进建议
- 当前文档体系保持轻量，不继续扩散抽象文档。
- 下一阶段优先细化 V1 的交互流程、模块边界和实现顺序。
